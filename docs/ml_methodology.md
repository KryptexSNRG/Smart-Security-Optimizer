# Machine Learning Methodology

## Purpose

The machine-learning component of the Smart Security Optimizer predicts whether a login event is normal or suspicious.

The target variable is:

```text
is_suspicious
```

Values:

| Value | Meaning |
|---:|---|
| 0 | Normal login |
| 1 | Suspicious login |

## Selected Features

The model uses login behavior features that are relevant to cybersecurity risk.

| Feature | Type | Why It Matters |
|---|---|---|
| `login_hour` | Numeric | Suspicious logins may happen at unusual hours. |
| `failed_attempts` | Numeric | Many failed attempts may indicate brute force or credential stuffing. |
| `mfa_failed_attempts` | Numeric | Repeated MFA failures may indicate MFA fatigue. |
| `mfa_used` | Boolean | Logins without MFA are generally riskier. |
| `new_device` | Boolean | New devices may indicate account takeover attempts. |
| `foreign_login` | Boolean | Foreign logins may be unusual for a user. |
| `unusual_hour` | Boolean | Late-night or early-morning logins may be suspicious. |
| `impossible_travel` | Boolean | Impossible travel is a strong sign of suspicious behavior. |
| `suspicious_ip` | Boolean | Suspicious IPs may indicate known risky sources. |
| `login_success` | Boolean | Successful logins after failed attempts may be risky. |
| `device_type` | Categorical | Different device types may show login behavior patterns. |
| `browser` | Categorical | Browser changes can help identify unusual login behavior. |
| `country` | Categorical | Location patterns can help detect foreign or suspicious access. |
| `mfa_type` | Categorical | Different MFA methods have different security strengths. |

## Excluded Features

Some fields are not used directly for prediction.

| Field | Reason Excluded |
|---|---|
| `login_id` | Identifier only; does not help prediction. |
| `user_id` | Could cause the model to memorize users instead of learning risk behavior. |
| `timestamp` | Raw timestamp is converted into `login_hour` and `day_of_week`. |
| `attack_type` | This is too directly connected to the target and would leak the answer. |
| `risk_score` | This is produced by the rule-based engine, so using it would make the ML model depend too heavily on the rules. |
| `risk_level` | Derived from `risk_score`, so it is not used as an input feature. |
| `recommended_action` | Output from the risk engine, not an input feature. |
| `risk_reasons` | Text explanation generated by the risk engine, not a raw login feature. |

## Models Used

Three baseline models will be trained and compared:

1. Logistic Regression
2. Decision Tree
3. Random Forest

## Evaluation Metrics

The models will be evaluated using:

- Accuracy
- Precision
- Recall
- F1 score
- Confusion matrix

For cybersecurity, recall is especially important because a false negative means a suspicious login was incorrectly classified as normal.

## Limitations

The model is trained on synthetic data, so performance may not match real-world cybersecurity systems. The current dataset is scenario-based, meaning suspicious events are generated by simulating known attack patterns. Future versions can improve the model by using more realistic behavior histories and calculated threat indicators.
